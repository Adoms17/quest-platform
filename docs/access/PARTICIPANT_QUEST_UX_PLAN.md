# Интерфейс участника квеста — план итерации

## Цель

Сделать начало и продолжение квеста понятным для участника, не ослабляя
серверную проверку доступа и не создавая попытку до осознанного старта.

## Этап 1. Стартовая страница

- После загрузки доступного квеста показать название, описание, количество
  заданий, способы проверки и расписание.
- Показать состояние сети и результат подготовки офлайн-пакета.
- Не создавать попытку и не запускать таймер до нажатия «Начать квест».
- Показать установленный организатором лимит прохождений для одного участника.
- Если в браузере сохранена попытка, использовать действие «Продолжить квест».
- Закрытый квест, недоступное расписание и отсутствие права обрабатывать до
  стартовой страницы существующими серверными проверками.

## Этап 2. Сводная страница заданий

- Показать список заданий и состояния: недоступно, доступно, выполняется,
  завершено, не пройдено, ожидает синхронизации.
- На сводной странице считать прогресс по завершённым заданиям, а внутри
  задания — по уникальным заданиям, которые участник уже открывал.
- Для последовательного режима разрешать переход только к текущему заданию.
- Полный безопасный набор заданий заранее сохранять в offline-пакет, чтобы
  прохождение не зависело от повторного подключения к сети. Будущие задания
  показывать на сводной странице в установленном организатором порядке, но до
  завершения предыдущего задания скрывать их названия и блокировать переход.
- Для произвольного режима разрешать выбор любого доступного задания.
- Если у заданий есть координаты, добавить общую карту с маркерами без
  раскрытия правильных ответов и секретных кодов. На карте показываются только
  места, которые организатор явно разрешил раскрывать; номера маркеров совпадают
  с номерами заданий, а доступный маркер открывает соответствующее задание.
  Цвет отражает состояние: доступное место — синее, завершённое — зелёное,
  недоступное — серое; неуспешное и ожидающее синхронизации дополнительно
  выделяются красным и жёлтым.
- При продолжении выбирать последнее активное или первое непройденное задание.

## Этап 3. Карта задания и оформление

- На странице задания показывать карту с ориентиром, если координаты разрешено
  раскрывать участнику до подтверждения местоположения. Разрешение задаётся
  организатором отдельно для каждого задания; для существующих заданий оно
  выключено. Разрешённые координаты входят в офлайн-пакет, а подложка
  OpenStreetMap загружается только при наличии сети. По явному действию
  участника карта может показать его текущую геопозицию отдельной отметкой и
  автоматически обновлять её до остановки пользователем или ухода со страницы;
  эта позиция не сохраняется и не журналируется. Точка задания подписывается
  её номером из сводной страницы. Для GPS-задания показываются точность
  геопозиции, приблизительное расстояние до места и серверный радиус проверки
  50 метров; эти данные являются подсказкой, а решение принимает сервер. Отказ
  в разрешении, недоступность позиции и таймаут объясняются отдельными
  пользовательскими сообщениями без вывода технического текста браузера.
- Обложка квеста хранится отдельным полем, редактируется организатором и
  показывается участнику на стартовой странице. Изменение защищено существующим
  разрешением `quests.update` и проверяется RLS-тестами.
- Короткий код можно ввести с главного экрана; нормализованный код передаётся
  в защищённую форму выбора участника и активации. QR-код для приглашений
  остаётся отдельным будущим улучшением.
- На стартовой странице показываются версия и приблизительный размер
  offline-пакета, время последней успешной серверной проверки доступа и срок
  действия автономного доступа для выбранного профиля участника.

## Ограничения безопасности и офлайн-режима

- Сервер остаётся источником истины для доступа, расписания, попыток и ответов.
- Данные самого квеста для участника загружаются только через whitelist-RPC;
  служебные `creator_id` и `organization_id` не входят в participant payload.
- Стартовая страница не должна получать правильные ответы, коды заданий или
  скрытые координаты.
- Полный offline-пакет не должен содержать правильные ответы, открытые коды,
  серверные секреты verifier или закрытые координаты. Названия, описания и
  разрешённые ориентиры всех заданий входят в пакет осознанно ради полностью
  автономного прохождения.
- Офлайн-пакет доступен только тому participant profile, для которого сервер
  подтвердил доступ при загрузке. Подтверждение действует 24 часа.
- Отзыв grant немедленно блокирует online-запросы. Уже загруженный пакет может
  работать без сети до истечения 24 часов с последней успешной серверной
  проверки; после reconnect сервер снова становится источником истины.
- Обновление приложения и IndexedDB не удаляет несинхронизированные события.
  Пакеты, попытки и события разделяются по participant profile.
- Миграция IndexedDB 8→9 добавляет индекс версии offline-пакета на месте и
  не пересоздаёт stores; браузерный тест сохраняет квест, активную попытку и
  pending-событие, созданные старой версией базы.
- Повторное нажатие или обновление страницы не должно создавать дубликаты
  активной попытки.
- Каждое offline-событие сохраняет неизменный `client_event_id`, пользователя и
  participant profile. После reconnect клиент сначала запрашивает серверные
  receipts и не отправляет повторно уже принятое событие. Если локальная
  попытка требует восстановления, она создаётся для профиля из pending-события;
  события разных профилей нельзя объединить в одну локальную попытку.
- Лимит прохождений проверяется сервером только при создании новой попытки;
  активную попытку участник может завершить, а `0` означает отсутствие лимита.

## Проверки этапа 1

- Компонентный тест стартовой информации и действий «Начать/Продолжить».
- Полный запуск Vitest, lint и production-сборки.
- Playwright smoke для публичных маршрутов и защиты страниц доступа.
- Playwright в настоящем браузере: изоляция пакетов между профилями и
  восстановление попытки с несинхронизированным событием после reload.
- Ручной smoke: новый участник, существующая попытка, offline-пакет, закрытый
  квест, квест вне расписания и отозванное право.
