# Работа Ромы и Дани

Владелец проекта — Алексей. Рома (Роман) — Мастер, Даня (Данила) — Помощник. Имена обозначают роли двух аккаунтов Codex, а не автоматическое предоставление прав. Договорённости утверждены Алексеем 21.09.2026. Память чата не является общим контекстом; этот документ сохраняет имена и правила в проекте.

## Ответственность

Рома ведёт очередь, зависимости, критерии, выполняет часть задач, принимает отчёт и PR, интегрирует и готовит выпуск. Даня выполняет только назначенную задачу, проверяет результат, обновляет документы и передаёт на Review. Алексей может проверять промежуточную работу и менять требования непосредственно со Даней. Повторное согласование с Ромой не нужно. Даня записывает согласованное изменение, последствия, новые критерии и зависимости в задачу и Notion. Существенные последствия для данных и безопасности объясняет до реализации. Рома принимает по актуальной постановке.

Уточнение требований не разрешает commit, push, merge, удаление данных или публикацию. Разрешение Алексея на конкретные действия фиксируется в задаче. Ни одна роль не отменяет AGENTS.md. Секреты и содержимое env-файлов не читать и не включать в передачу.

## Источники информации

- AGENTS.md — постоянные обязательные правила, без журнала работ.
- Notion — концепция, бизнес-правила, решения и дорожная карта. Оба аккаунта должны отдельно проверить подключение. Даня может читать и обновлять связанные страницы в рамках задачи; не переопределяет решения владельца самостоятельно.
- GitHub Issues — исполнимые задачи, границы, критерии, зависимости и согласованные изменения.
- Репозиторий — технические контракты, инструкции, миграции и тесты; docs/tasks — локальные поручения до размещения в Issues.
- PR — изменения, проверки и ревью. GitHub Project необязателен.
- Чат — коммуникация; значимые решения переносятся в задачу/документацию. При противоречии источников зафиксировать вопрос, не выбирать молча.

Если Notion недоступен, сохранить предлагаемый текст в отчёте, сообщить ограничение; не заявлять, что страница обновлена. Ссылки на изменённые страницы обязательны в отчёте.

## Цикл задачи

Backlog → Ready → In progress → Review → Done. Ready означает, что поручение исполнимо без чата Ромы. До Ready заданы исходный commit, путь рабочей копии, ветка codex/<идентификатор>, область, проверки и критерии. Зависимые работы последовательны. Одновременные изменения одного файла/контракта запрещены. Статус выпуска ведётся отдельно: локально / stage проверен / prod опубликован. Done не означает разрешение на deploy.

По умолчанию отдельный worktree на задачу. Создание от точного согласованного commit; незакоммиченные изменения автоматически не переносятся. Один checkout допустим только при чистом git status и завершённой передаче. Не создавать копию от staging, ожидая увидеть локальные незакоммиченные акции. Не выполнять reset/clean/stash или удаление рабочих копий для освобождения места без разрешения.

## Начало и завершение сессии

1. Прочитать AGENTS.md, это руководство, задачу и последний отчёт; проверить git status, branch, HEAD и worktree list.
2. Сверить ожидаемый исходный commit и чужие изменения. При расхождении не исправлять историю автоматически.
3. Проверить доступы GitHub/Notion текущего аккаунта без вывода токенов. Общая авторизация CLI Windows не доказывает независимость аккаунтов; user.name в Git — автор commit, не роль Мастер/Помощник.
4. Проверить журнал ресурсов: порты, процесс, абсолютный config Vite, контейнер/база, применённые миграции. Worktree не изолирует Docker и БД. Не останавливать неизвестные процессы.
5. Выполнить задачу и проверки. При окончании записать git status, изменённые файлы, фактические команды/результаты и состояние ресурсов. Не передавать секреты и реальные коды.
6. Даня переводит в Review; Рома проводит ревью и необходимые интеграционные проверки, затем Done либо возвращает замечания.

## Проверки и выпуск

PowerShell: npm.cmd run lint и npm.cmd run build — минимум. Дополнительно по области: npm.cmd test -- admin --maxWorkers=2; npm.cmd run test:e2e -- --config admin/playwright.config.mjs (при отсутствии bundled Chromium: PLAYWRIGHT_ADMIN_CHANNEL=msedge). Синтетический браузерный тест не является проверкой реального API или Safari.

Миграции и RLS: изменения схемы только миграциями, проверки чужой организации, MFA, отзыва прав и retry. Для текущего тарифного пакета: QVESTA_TEST_TARIFF_RELEASE=1; npm.cmd test -- scripts/tariff-release-migrations.test.js --maxWorkers=1. Harness создаёт временную БД; не reset общей базы. Проверять фактическое число миграций в harness, не копировать старое число из отчёта. Удалённые миграции — отдельный разрешённый выпуск с проверкой истории и dry-run.

Offline: обязательны идемпотентность client_event_id, сохранность неотправленных результатов, восстановление после перезапуска и миграции IndexedDB. Выбрать существующие профильные тесты и привести команды в поручении; отсутствие проверки критической логики явно указывать.

Поток: задача → ветка → разрешённый commit/push и PR → ревью → разрешённая интеграция → stage → приёмка → отдельное решение Алексея по prod. Проверять автодеплой Cloudflare до push/merge: публикация может быть следствием Git-события. Ни слияние PR, ни Done не разрешают автоматическую публикацию prod. Существующие внешние автодеплои должны быть проверены и при необходимости перенастроены отдельным согласованным действием.
