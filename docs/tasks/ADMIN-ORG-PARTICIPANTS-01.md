# ADMIN-ORG-PARTICIPANTS-01 — профили и группы в карточке организации

Статус: реализация локально. Исходная ревизия 61d9c0774fcc07a278613fe5c357039ee97b4e19, ветка codex/organization-participants, рабочая копия organization-participants.local. Журнал предыдущего выпуска сохранён в recurring-acceptance.local без изменений.

## Согласованный контракт

Алексей выбрал подробный вариант вместо минимальной сводки. Подтверждены вкладки «Квесты / Профили / Группы», поиск и переходы профиль → группы → участники. Только чтение, owner/operations с MFA в пределах действующего назначения. Контакты, даты рождения, сведения о представителях, ответы и данные попыток не выдаются.

Дополнительное уточнение подтверждено: показывать только профили, участвовавшие в квестах организации; в их группах скрывать остальных участников. Группы не принадлежат организации. Связь определяется существующей попыткой квеста организации; профиль определяется participant_profile_id попытки. Архивные профили сохраняют собственную строку; биллинговая эквивалентность профилей не подменяет их личность. Удалённые попытки не восстанавливаются из биллингового учёта. Это реестр по сохранившимся данным, не месячная тарификационная сводка.

Поля профиля: имя, возрастная категория (включая «не указан»), архивный статус. Возраст не выводится из self/dependent. Группы и членство показываются текущие активные, не исторические на дату участия. Общий размер группы и скрытые участники не возвращаются. Каждый список ограничен 25 строками с курсором, связанным с организацией и фильтрами. Отказ очищает данные; поздний ответ прежней организации игнорируется.

## План и критерии

1. Отдельное право, RPC и аудит без расширения пользовательских RLS. Проверить чужую область, роли, MFA, отзыв, истечение, приватность, смешанную группу и курсоры.
2. Вкладки, общий data layer, состояния загрузки/ошибки/пустого списка, переходы и пагинация. Проверить смену организации и гонки ответов.
3. Изолированный replay миграций, UI/API, lint, сборки и браузерная проверка. Затем подготовка отдельного выпуска backend перед frontend. Commit/push/merge/deploy этим согласованием не разрешены.
