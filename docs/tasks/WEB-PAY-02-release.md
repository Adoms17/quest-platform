# WEB-PAY-02 — выпуск на stage

Разрешение: Алексей поручил полный выпуск на stage и браузерную приёмку без дополнительных подтверждений (26.09.2026).

Состав: семь миграций 20260926010000–20260926016000; чтение и принятие документов в discount checkout; историческая запись принятия; ограничение исполнения для включённых тестовых рабочих областей. Массовое переименование и юридические тексты сайта в этот выпуск не включены.

Порядок: CI → merge staging → purchase-documents-dry-run → purchase-documents-apply → purchase-documents-fixture → браузерная приёмка. Манифест WEB-PAY-02-migrations.json содержит точные контрольные суммы. Фикстура разрешена только в staging workflow, выбирает существующую sandbox-future-fast, не меняет её подписку и не отправляет платежи. Два явно необязательных тестовых текста и предложение 2 ₽; не коммерческая публикация. Нет создания аккаунтов или расширения пользовательских прав.

UI включён сборкой --mode staging; реальное требование определяется read_checkout_document_scope для рабочей области. Старые рабочие области продолжают прежний поток. Существующие заказы не получают согласие задним числом. Отключение: убрать рабочую область из scope доверенной административной операцией и выключить build flag; историю принятия не удалять.

Приёмка: документы видны до заказа; кнопка заблокирована без согласия; точные тексты открываются; новый расчёт сбрасывает галочку; согласие создаётся с заказом; обновление страницы восстанавливает тот же заказ и редакции; отмена не отправляет платёж и сохраняет подписку. Платёжный провайдер и реальные деньги не входят в эту проверку документов.
