## Операции расписания

В deploy-staging добавлены subscription-settlement-schedule-preview/provision/enable/disable. Перед первыми тремя проверяется применённая схема; disable доступен без проверки истории миграций. Preview откатывает транзакцию. Provision сохраняет только выключенный допуск. Enable сначала выключает флаг функции, выполняет preview, задаёт точный ID и включает флаг, затем повторяет допуск и атомарно включает строку и cron. Если проверка не прошла, строка и cron не активируются. Шаги failure/cancelled закрывают флаг и расписание отдельно. Принудительное завершение runner может помешать cleanup: в этом случае оператор запускает disable и проверяет результат; уже отправленный запрос не считается отменённым.

SQL проверяет наличие выключенного cron с ожидаемой командой и имени учётных данных в Vault, не извлекая секрет. Совпадение ключей Vault/функции и доставку HTTP подтверждает только последующая stage-приёмка. Повтор enable после использованного допуска намеренно запрещён; при неизвестном результате — сверка существующей операции.

Локально: 13 проверок (включая полный SQL/RLS стенд, 79.20 с) и 64 проверки совместимости прошли. Lint и сборка приложения прошли.
