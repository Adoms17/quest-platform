# Локальное согласование автопродления с OPS-01.4

Основа: PR183 `fe01bfc9eb9c0a05c45775104c854816c8215bb4`. Подготовка без публикации, активации платежей, migrations или изменения прав.

## Исправлено

- Agreement/PaymentTerms больше не исключают автопродление из полного MVP. Сохранены draft-статус документов, прежние цены, trial, SHOP и возвраты. Добавлены только зафиксированные OPS-01.4 правила отдельного согласия, закреплённой версии, скидок, отказа, идемпотентности и предупреждения за 30 дней.
- Согласие и управление им показывают общий компонент правил `RecurringTerms`, чтобы условия версии, льгот и отзыва не расходились.
- Статус после отзыва говорит о запрете следующих списаний и необходимости проверить уже начатый платёж. Он не обещает отмену отправленной операции. Повторное чтение отозванного согласия не вызывает новый запрос согласия или отзыв.
- Новый локальный Vitest config не читает `.env` и содержит явный allowlist синтетических browser/UI suites. Он не включает B17 или интеграционные базы.

## Что остаётся блокером коммерческого включения

1. `sandboxCheckoutVisibility.js`, `VITE_SANDBOX_RECURRING_SETUP`, sandbox RPC, worker enable guards и merchant bindings оставлены прежними. Ни копия интерфейса, ни смена слова «тестовый» не делают их production контрактом. Нужны точные проверенные production API/bindings и отдельный допуск активации; новые RPC/флаги/секреты не придуманы.
2. Юридическая окончательная редакция согласия и доказательство его принятия/отзыва, обязательные уведомления и фискальная модель АУСН для обоих продуктов ещё требуют подтверждения. Используется существующая версия `sandbox-recurring-v2`; она не объявляется утверждённой live-версией.
3. Не изменены обработка unknown, граница dispatch и политика прекращения продлений. Исторические SQL/компонентные тесты не заменяют provider/hosted приёмку.
4. Production ledger99→335, managed prerequisite security delta, restore proof, полный SHOP journey и B17 остаются прежними gates. Полный продукт не сокращён.

## Безопасная локальная проверка

`npm test -- --config vitest.local-alignment.config.js ...` позволяет явно перечислить нужные тесты. Для двух browser suites требуются только `QVESTA_TEST_ACCOUNT_ACTIVITY_BROWSER=1` и `QVESTA_TEST_PARTICIPANT_BROWSER=1`; их Vite fixtures используют localhost и синтетический Supabase, внешние запросы блокируются. Это отдельный временный Chrome без личного профиля, не инструмент управления браузером пользователя.

Локальные smoke/регрессионные результаты и точные команды сохранены во внешнем отчёте задачи; не являются разрешением на push/merge/rollout.
