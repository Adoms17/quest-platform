# PROD-PAY-05 — подготовка stage-пакета guard/pin

Дата: 01.10.2026. PR #151 слит в staging: `58b1fdabbf4f9da18f9338e773fe2fdf853189c9`. Этот документ описывает локальную подготовку следующего выпуска. Удалённое применение НЕ выполнено.

## Локальный сборщик

`scripts/build-stage-billing-guard.js` проверяет существующий manifest и хеши обоих SQL-кандидатов, затем объединяет guard → pin → первоначальную запись `sandbox` в одну транзакцию. Сборщик только печатает SQL; подключения к БД нет.

Команда из корня проекта: `node scripts/build-stage-billing-guard.js jeugfyaqzfgdvfhdxfht`.

Параметр project-ref ограничивает генерацию, но не удостоверяет сервер, на котором кто-то исполнит SQL. Advisory lock координирует только исполнителей с тем же ключом и не останавливает платёжные процессы. Лимиты ожидания блокировки и отдельного SQL statement — 5 и 60 секунд. Пакет предназначен для однократного применения; повтор после неизвестного результата требует сначала чтения состояния, а не слепого запуска.

## Следующая итерация: исполнитель выпуска

1. Зафиксировать одобренный commit нового пакета и хеш сгенерированного SQL. Проверить фактический stage project-ref, историю миграций и отпечатки функций. Остановиться при любом расхождении. Текущий manifest сохраняет статус `local-candidate-not-deployable`.
2. Инвентаризировать все отправители платежей, возвратов и чеков, расписания, флаги и уже взятые задания. Подготовить конкретный порядок остановки и доказательство отсутствия запросов в полёте. Выключения трёх флагов чеков недостаточно. Проверить полномочия hosted postgres отдельно от локального superuser.
3. После разрешения stage-выпуска остановить отправителей и исполнить проверенный пакет одним соединением с остановкой на первой SQL-ошибке. Не применять общий `db push` вместо этого пакета.
4. Прочитать закреплённое значение `sandbox`, проверить ACL/RLS и определения функций, сохранить техническое свидетельство без секретов. При потере соединения сначала сверить состояние; не запускать новый пакет автоматически.
5. Выполнить [приёмку без новых платежей](PROD-PAY-05-stage-acceptance.md). Возобновление отправителей оформить отдельным явным шагом после приёмки. Production этим выпуском не затрагивается.

До COMMIT ошибка откатывает пакет целиком. После успешного COMMIT нельзя обещать обратное переключение среды: pin запрещает её изменение. План восстановления после COMMIT должен сохранять остановленные отправители и использовать отдельно проверенное исправление.
