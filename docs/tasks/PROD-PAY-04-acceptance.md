После PR #157 общий sandbox gate выключен. По subscriptionFiscalRefundRuntime.js и subscriptionFiscalRefundEndpoint.js ответ sandbox_disabled (503) возникает до authenticateRefundOwner: он НЕ закрывает проверку JWT/MFA/роли. Проверка gateway без Authorization (401) также не доказывает отказ настоящему истёкшему JWT.

Порядок оставшейся приёмки:
1. Отдельный non-admin аккаунт: вход в stage-admin, поиск организации и проверка отсутствия данных; отдельно фиксировать видимость меню. Вход запрошен у владельца, результат ещё не получен. Текущий App.jsx после aal2 показывает меню без отдельной проверки роли — UX-пункт остаётся открытым.
2. Настоящий aal2 JWT с MFA старше 300 секунд, но с exp в будущем: ожидать authentication_required (401). Синтетические claims, изменение часов и подделка подписи не считаются stage-доказательством. Секреты/токены не переносить в чат, файлы и логи.
3. Настоящий истёкший JWT: дождаться фактического exp при контролируемой тестовой сессии; автоматическое обновление токена не должно подменять проверяемый экземпляр. Отдельно фиксировать, где отказал запрос — gateway либо handler.
4. Non-admin с ещё свежим MFA и действительным JWT: отказ прав должен быть отличим от отказа MFA. Проверять только заранее ограниченную тестовую цель. Нельзя использовать execute существующей операции возврата для отрицательного теста: неожиданно успешная авторизация может вызвать финансовый эффект.
5. До включения endpoint подготовить конкретные запросы и проверку отсутствия новых reserve/command/attempt; существующие завершённые заказы не перепроводить. Включение глобального gate для этих тестов требует отдельного окна и ограничения отправки на уровне сценария. В текущем срезе флаги не включались, HTTP-пункты не закрыты.

Следующее инженерное решение: отделить безопасную приёмку Auth/permission от execute либо использовать существующий read-only контракт, если он проверяет те же полномочия; отдельный диагностический маршрут не выдавать за проверку реального refund endpoint. Любое расширение серверного контракта проходит обычные тесты/PR/CI до stage.
