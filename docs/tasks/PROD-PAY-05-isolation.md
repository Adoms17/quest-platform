## Требования к следующему изменению

### Самодостаточный SQL-стенд для CI — 01.10.2026

production-baseline-migrations.test.js больше не читает схему из supabase_db_quest-platform. В своей одноразовой БД запускает миграции закреплённого supabase/gotrue:v2.196.0 через общий с БД network namespace без внешней сети и опубликованных портов. auth.uid/auth.jwt/auth.role создаются самим Auth; проверяется их наличие. Итоговый полный прогон без общей локальной БД PASS (104.03 с); lint/build/manifest/diff-check PASS. Первые попытки выявили дублирование штатной auth.jwt и затем расхождение окончаний строк; оба исправлены. Сборка первоначально не могла записать временный файл вне sandbox writable-root, повтор в host-контексте прошёл.

### Порядок блокировок и локальный состав — 01.10.2026

Статический разбор общего подтверждения: advisory lock идентификатора → строка подписки FOR UPDATE → INSERT подтверждения → trigger → строка среды FOR SHARE. В защищённых sandbox-точках строка среды берётся раньше доменных блокировок. Два FOR SHARE совместимы; само это различие не образует цикл ожидания между двумя читателями среды. Это вывод по коду, не новый конкурентный тест всей цепочки.

При работающих обработчиках нельзя оставлять промежуток между guard и pin и менять среду оператором: операция, удерживающая подписку, может ожидать настройку. Для будущего выпуска зафиксирован порядок: историческая схема → guard → pin → явное назначение среды → совместимые workers, при остановленных конкурентных записях/обработчиках. Pin запрещает штатную смену идентичности; вмешательство оператора с изменением DDL не покрывается этой защитой. Не объявлять все доменные блокировки проверенными.

Создан `PROD-PAY-05-candidate-manifest.json`: точные SHA-256 двух кандидатов и агрегат 324 исторических файлов (упорядоченные имя, NUL, SHA-256 файла, LF). Проверка: `node scripts/verify-production-candidate-manifest.js`. Валидатор только читает локальные файлы, не подключается к БД. Положительная проверка PASS; неверные хеши кандидата и цепочки отдельно отклонены, исходный manifest восстановлен и повторно проверен. Lint/build PASS. SQL в этом шаге не менялся; предыдущий интеграционный результат 108.43 с остаётся последним SQL-прогоном.

Статус manifest — local-candidate-not-deployable. Это фиксация локального состава, не release manifest: нет утверждённого commit/SHA, CI из release-checkout, списка функций выпуска и процедуры конфигурации stage. Точное хеширование учитывает окончания строк; перенос в CI должен подтвердить те же байты. Следующий шаг — подготовить процедуру проверки состава в CI и согласованный порядок миграционного пакета, не запускать общий production db push.

### Фиксация исходных тел SHA-256 — 01.10.2026

В начало SQL-кандидата встроен реестр SHA-256 prosrc для всех 34 изменяемых функций: 32 безусловные защиты и две условные. Хеши получены из отдельной БД после 324 исторических миграций. До создания таблицы среды и любых замен проверяется каждое исходное тело; отсутствующая функция или несовпадение останавливают транзакцию с указанием сигнатуры. Хеши не вычисляются заново для автоматического принятия изменённой базы.

Негативный тест с добавленным комментарием теперь проверяет source hash mismatch и отсутствие частично созданной таблицы. На исходной схеме весь интеграционный прогон PASS (101.23 с), lint/build PASS. Временный режим сбора и файл хешей удалены; реестр находится непосредственно в SQL-кандидате. Stage и production не менялись.

Проверяется точный текст тела, включая форматирование. Перед выпуском нужно подтвердить совместимость в CI из release-checkout, особенно окончания строк; при несовпадении разбирать причину, не обновлять хеши автоматически. Этот реестр не фиксирует отдельно ACL, владельца и все атрибуты функций и не доказывает полноту списка рабочих путей. Следующий этап — аудит покрытия вызовов и формирование проверяемого состава миграционного пакета.

### Первичное назначение production — локальный кандидат

В production-environment-pin.candidate.sql добавлен BEFORE INSERT preflight. Для production проверяются billing_sandbox_*, billing_recurring_*, checkout-история, trial paid-periods, тестовые fixtures, receipt snapshots, фискальные операции и общие подтверждения периодов; отдельно отклоняется sandbox-фискальная политика. Проверка намеренно консервативна: общие исторические подтверждения тоже требуют разбора, даже если их происхождение пока неизвестно. Тарифный каталог и сами организации не препятствуют назначению.
