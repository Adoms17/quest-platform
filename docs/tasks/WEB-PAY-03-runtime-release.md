# WEB-PAY-03 — функции и интерфейсы чеков

27.09.2026, локальный пакет в codex/receipt-runtime-stage, база 68c9408. Схема чеков уже применена на stage; этот пакет ещё не опубликован.

Включает обработку чеков ручной оплаты, автопродления и возвратов; GET-сверку чеков и зачёта; просмотр статусов в карточке платежа админки; форму email для чека за VITE_SANDBOX_RECEIPTS. Без этого frontend-флага форма не появляется.

Новая операция deploy-staging.yml: receipts-functions-deploy. Перед выпуском требует применённый manifest схемы, затем устанавливает false для YOOKASSA_SANDBOX_RECEIPTS_REQUIRED, YOOKASSA_SANDBOX_RECEIPT_RECONCILIATION, YOOKASSA_SANDBOX_SETTLEMENT_RECONCILIATION. Публикует только sandbox-checkout, sandbox-recurring, sandbox-reconcile, admin-sandbox-refund, admin-subscription-refund. Не меняет базовые флаги платежей/автопродления и не создаёт политику чеков.

Выключенный required-флаг не удаляет ранее подготовленный чек и не отменяет восстановление уже начатой операции. Перед приёмкой учитывать существующие фискальные данные. Политики с неподтверждёнными параметрами не создавать. Частичные фискальные возвраты и автоматический момент зачёта остаются открытыми.

Проверки: 417 тестов функций и компонентов прошли (37 файлов); отдельно 5 тестов checkout с добавленным сценарием legacy-покупки без поля receipt. Lint и основная/PWA-сборка успешны, существующие lint-предупреждения сохранены. Admin test build успешен (предупреждение о размере bundle). Edge Runtime: первоначально sandbox-recurring не успел стартовать, sandbox-reconcile прошёл. После увеличения лимита ожидания до 60 с и добавления диагностики оба теста прошли за 18,96 с; причина первого тайм-аута не установлена.

Следующее: PR/CI и разрешённый выпуск функций, затем браузерная приёмка административного просмотра и совместимости старой sandbox-покупки. Реальной проверки ЮKassa и публикации этим шагом не было. Production не входит в пакет.
